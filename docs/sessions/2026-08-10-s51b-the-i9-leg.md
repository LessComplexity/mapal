### 1a. S51 did not touch this box, and that was proven not assumed

`raptorlake` records no SME unit, so `pack_pays` is never asked (the threshold is scoped to
sites taking the SME rung). **Verified by hash: `nn4_{128,512,2048}` × {exact, contract}, all
six emissions byte-identical before and after S51.** The ladder above is therefore a clean
baseline, not a measurement of this session's change.

### 1b. The 1-thread gap reproduced independently

**0.82–0.96×, flat across a 16× size range.** S50 characterised it as 0.87–0.96× from a
different run on a different day; this is an independent confirmation that it is a
size-invariant micro-kernel deficit against OpenBLAS on the same AVX2 units, not a blocking
failure. It is the one term S51 did not touch and does not claim to.

### 1c. Most of the threaded "win" below d=1024 is OpenBLAS threading, not mapal

`numpy-mt` is **worse than `numpy-1t`** at every size under 1024 on this box:

| d | numpy 1t | numpy mt | threading is |
| ---: | ---: | ---: | --- |
| 128 | 0.1378 | 0.5131 | **3.7× worse** |
| 256 | 0.9058 | 1.6557 | 1.8× worse |
| 512 | 6.7245 | 8.0647 | 1.2× worse |
| 1024 | 52.16 | 8.2945 | 6.3× better |
| 2048 | 414.49 | 57.583 | 7.2× better |

So every threaded verdict here is quoted against numpy's **best** leg, the handicap S43
adopted. Against `numpy-mt` alone the d=512 rows would read 8.8× and 9.1× instead of 7.31×
and 8.41×; the smaller number is the honest one and is what goes anywhere public.

### 1d. NEW — a scaling hole at d=1024, unexplained

mapal's own 32-thread scaling (`nn4`, fma, 1t ÷ par):

| d | 128 | 256 | 512 | **1024** | 2048 |
| --- | ---: | ---: | ---: | ---: | ---: |
| scaling | 0.95× | 3.50× | **8.12×** | **6.15×** | 9.37× |

Non-monotone, and d=1024 is the only size on this box where mapal loses to numpy (0.86–0.91×).
The overlap factor `W = 2·T(nn2)/T(nn2x2)` reads **0.730** there on the fma-par leg — below 1,
i.e. two independent nets run *slower* than the same flops chained, which is the opposite of
what the DAG should buy. Recorded as an open question; **not** diagnosed here.

## 2. Constants — one of three

| field | value | how |
| --- | ---: | --- |
| `flops_per_ns` | **144** | `nn4_1024` 59.5654 ms → 144.2 GF/s; `nn4_2048` 479.33 ms → 143.4. Tight, and the same recipe that gave the M4 its 1000 |
| `bytes_per_ns` | **owed** | `saxpy_1048576` at `MAPAL_PAR=1`; emitted and cross-compiled, never ran |
| `dispatch_ns` | **owed** | the nn4_128 difference; both arms built, **8 flipped tasks confirmed from the emission** |

`raptorlake` therefore still carries `dispatch: None` and still dispatches everything — which
is the correct state, not a gap: no part is made worse by a number nobody took.

### 2a. Why `dispatch_ns` needs a scratch profile at all

It can only be measured as a **difference**: dispatch everything (`raptorlake`,
`dispatch: None`) against inline everything, over the number of tasks that flip. There is no
"inline everything" without an emitter that answers `inline` for every site, so
`RAPTORLAKE_INLINE` exists — `raptorlake` with `dispatch_ns = 1_000_000_000`.

**The divisor is counted from the emission, not assumed.** The script diffs the two arms'
`mapal_par_task` kind arguments and hard-errors if nothing flipped. On `nn4_128` it is **8**
(four matmul slices + four pack tasks) — the same count the M4 had, but arrived at by counting.

### 2b. `handoff_floor` is NOT the source, and the record says why

S50 used its parked-wave figure (30 µs), which over-priced a real dispatch by 3.6× and
regressed three cells 5–20% (`conv2d_512` 0.805×, `matmul512` 0.944×, `nn4_512` 0.945×). The
shipped M4 value is a program difference, and this script derives raptorlake's the same way.
**Do not substitute the microbenchmark because the box is flaky** (rules 25 + 26).

## 3. Decisions

| Decision | Verdict | Why |
| --- | --- | --- |
| Quote threaded verdicts against numpy's **best** leg | kept | `numpy-mt` is worse than `numpy-1t` below d=1024 here; quoting against mt alone would inflate mapal 1.1–1.2× |
| Derive `dispatch_ns` from a program, not `handoff_floor` | kept | The microbenchmark's own recorded failure (§2b) |
| Count the flipped-task divisor from the emission | kept | Assuming 8 because the M4 had 8 would put this box's error straight into the constant |
| Leave `RAPTORLAKE_INLINE` in the tree | kept, **with a P0 to delete it** | The measurement can resume the moment the box returns; re-adding it costs a rebuild. It is reachable only by explicit name and is loudly marked |
| Ship a partial `DispatchCost` from one field | **discarded** | `DispatchCost` is all-or-nothing; a `Some` with two guessed fields is exactly "a number nobody took" |
