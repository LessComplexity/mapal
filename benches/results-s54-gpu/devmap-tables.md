# S54 `devmap` (R2) and `cell-law`: per-cell maps as device kernels, five parts

Build `s54/devmap` @ 007d367 (`cell_plan` + `launchv` from `s54/epilogue`, then this item). Measured
2026-10-21 on vast.ai: one session per part, plus a confirm session on a different box for H100 PCIe and
A100 (`ew`, `residual`), every rental destroyed. Arms interleaved per repetition in one session: `on`
(shipped), `off-devmap` (the s54-base placement, byte for byte), `off-cell-law`. Mapal's number is its
own clock (`iter ms`; the clock fence waits for the device and, since this item, for an eager init);
kernel = the MAPAL_GPU_TRACE launch time of the sites and cells (each launch synchronized, so it
includes launch latency). Library legs: `chain_bench.cu`, cudaEvent medians after a 256 MB L2 flush,
gated against Mapal's printed values. Raw rows: `devmap-<part>.txt`; static counts:
`devmap-fusion-report.txt`.

## What the numbers say

- **Correctness.** Differential 72/72 on every part (both faces; arms on, off-devgen, off-devmap,
  off-cell-law; `px_ewc_128` is `ew`'s device path read at eight cells, `px_ew_128` its whole-read
  negative control on the host), 16/16 on both confirm boxes. Library gates 54/54 per part.
- **`devmap` pays on every probe, part, size and face.** Site probes 1.30–4.76× (H100 PCIe up to
  15.5× on a noisy box), `loop` 1.76–2.53×, `ew` 4.4–121×. What it removes is in the static report:
  every intermediate stays on the device (d2h only the printed corners, h2d 0 except the loop's initial
  state), no per-cell host loop is left.
- **`cell-law` pays on `ew`, nowhere else measurable.** `ew` at 4096: 1.11–9.32× (H100 PCIe 2048
  contract measured 0.66 on the base box and 1.25 on the confirm box: no stable sign at that size).
  `residual`: 0.98–1.02 (its operand is a tile site's, built either way).
- **`ew` against the library's fused kernel** (which reads two 64 MB inputs; Mapal's kernel reads
  nothing and evaluates both closed-form operands per cell): kernel time at 4096 is 1.97× (3090),
  3.66× (4090; the 64 MB output fits its 72 MB L2), 2.02× (5090), 0.93× / 1.32× (A100 base / confirm
  box), 0.95× / 1.29× (H100 PCIe base / confirm). At 2048: 0.54–2.06×. On A100 and H100 the kernel is
  compute-bound: each cell runs two IEEE `div.rn.f32` (the oracle's bits) and lands at 23–35% of peak
  bandwidth, against 58–109% on the GeForce parts. Mapal's own clock at 4096 beats the fused leg only
  on the 4090 (1.30–1.39×); elsewhere it is 0.08–0.81× because the clock includes the output's
  `cuMemAlloc` (0.2–0.9 ms for 64 MB).
- **Losses against the best library chain** (Mapal's clock, 4096, contract face): 3090 0.56–0.81,
  A100 0.58–0.65, 4090 0.40–0.61, H100 PCIe 0.35–0.91, 5090 0.44–0.68 on the site probes; `loop`
  0.08–0.32 everywhere. Kernels alone (contract, 4096) are 0.74–1.14× the library chain: above 1.0 on
  the 3090 (1.05–1.14), on the 4090 (up to 1.11) and the H100 (up to 1.02); exact face 0.38–0.70×.
- **Where the rest of the gap is** (the traces and the emitted host IR; not this item):
  `cuMemAlloc` + `cuMemFree` inside the clock, 1–13 ms per probe at 4096 (R6 `arena`); in `loop`,
  Mapal's clock is 137–360 ms against 17–124 ms of kernels — the host text still runs five 64 MB
  `memcpy`s per step on the device-carried state (the loop product's `Proj` view, `Pair` and back
  edge; the host copy is never read), plus the 64 MB initial upload; the exact face's two instructions
  per MAC.
- **R2's price where R1 would fold** (`mlp` on this branch, no epilogue): the cell kernel adds
  0.02–0.13 ms at 2048–4096 (ON kernel − off-devmap kernel; 3090 0.2–0.5 ms, noisier) to two sites.
