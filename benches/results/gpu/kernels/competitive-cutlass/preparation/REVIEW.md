# Competitive FP32 GEMM reference review

This benchmark-only derivative makes the pinned CUTLASS reference an explicit finite tuning study. Twelve source-audited SIMT tile choices include the original default control, row-fitting tiles, and smaller M/N tiles yielding up to 256/512 independent-output CTAs for the two initial representative shapes. Runtime legality and profitability remain unproved until actual CUDA compilation and hardware gates.

The initial finite workload is the existing two M16 families, both Mapal Exact/Contract faces, their full bounded checks, and their representative sampled requests. It is not a generic selector and does not cover the prior wider/16K history, M128 neighbors, large controls, recurrence or other algorithms. Those can be added through an explicit expanded manifest. This study does not add primitive gains together or establish compiler-fusion advantage.

The frozen harness, original PTX, Mapal launch statement, cuBLAS SGEMM statement, random input generator and entire ordinary timing tail remain unchanged. The new source selects a named CUTLASS SIMT instantiation, requires precomputed scalar references, emits raw checked bits and resource/configuration metadata, and adds an isolated profiling branch. `generation-receipt.json`, `candidates.json` and `local-test-evidence/` bind those claims. The default type and cuBLAS DEFAULT_MATH arm remain named controls; there is no silent TensorOp or TF32 replacement. `NVIDIA_TF32_OVERRIDE=0` is required and recorded. DEFAULT_MATH alone does not identify cuBLAS execution units.

The numerical budget uses the existing mathematical exact-input dot bound `2*gamma(2K)*S + 4K*2^-149`, where `gamma(n)=n*2^-24/(1-n*2^-24)`, and now computes its binary64 ceiling exactly. For the frozen input law, A and B are integer q/2^23 values. The generator verifies that lattice, accumulates `S_num=sum(abs(qA*qB))` with arbitrary-precision integers, and forms the exact rational `2*K*S_num / ((2^23-K)*2^46) + 4*K/2^149`. It converts that rational to binary64, compares the conversion back to the exact rational, and advances by one representable value only if needed. Assertions prove that the result encloses the rational and its predecessor does not. All sum/bound numerators and denominators are exported for independent audit. An earlier unexecuted preparation using fsum plus only one final nextafter was rejected during source review because rounded intermediate gamma/products do not establish an upper bound. No GPU observation or fitted tolerance influenced this correction.

The frozen inputs lie in [-1,1), and K is at most 7168 here. Their products and nonzero ordered-fold lattice units are at least 2^-46, avoiding underflow for those reference operations; magnitudes remain far below overflow. The inherited conservative 4K*2^-149 allowance is retained. This is a bound defining the accepted output budget, not proof of an unknown closed-library algorithm's implementation. Separate-operation FP32 references force volatile float product/accumulator with contraction off; the second reference calls true C fmaf through a volatile function pointer under round-to-nearest. A cancellation test distinguishes the two. The authoritative Python checker compares errors as exact rational differences of actual/reference float32 values. The C++ pre/post gate conservatively rounds the absolute double-subtraction error upward before comparing, so rounding cannot create a false pass.

Every checked actual value from all three implementations must be finite and within its componentwise bound against BOTH scalar references. Mapal additionally retains its declared ordered-bit requirement. Library tolerance admission is never labeled an ordered-bit guarantee. Full bounded cells and the exact existing 256 representative cells are retained, including repeated sampled coordinates. Raw pre/post bits allow the independent checker to reproduce every admission without CUDA.

The ordinary entry point is `python3 run_competitive.py --out ABSOLUTE_FRESH_OUT --total-timeout 900`. Read-only validation is `python3 run_competitive.py --check-only`. The exact binary is reused for full/sampled gates, tuning, confirmation and later profiling.
