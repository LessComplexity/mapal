# GPU optimization experiments ranked by evidence

The measured gaps are real within their admitted cases; their causes remain open. The first useful compiler work is to discriminate realizations using facts already available, while keeping ordered arithmetic separate from any new numerical permission. No selector or IR-policy change follows automatically from this plan.

Evidence scope is deliberately separate: the primitive tuning ran on driver595.91.07; the fused program comparison on driver580.142; earlier callback images and panel tests have their own recorded hosts. Their medians are not pooled. `evidence-index.json` binds the reports used here without repeating completed raw-word/hash audits.

References E1–E8 are exact paths/hashes in `evidence-index.json`.

## What is proved

- At M16/N2048/K7168 and M16/N1024/K4096, tuned FP32-SIMT CUTLASS16×64×16 is2.32–2.34× faster than its old128×128×8 default in held-out samples. The32-thread16×32×8 configuration is the slowest tested, and the finer8×32×8 configuration is legal but does not win. This supports searching legal geometry; it does not prove that more blocks, more threads, or deeper panels independently cause a gain. cuBLAS remains4.31–7.01× faster than selected CUTLASS in these cells. [E1]
- On the two M128 residual-MLP shapes, Mapal steady wall medians are73.090/128.935µs; tuned fused Lt is32.659/59.620µs. With identical selected opaque Lt configurations across modes, unfused→fused is36.255→32.659µs and63.416→59.620µs. These are fresh-process median observations, not isolated fusion-cost estimates. The source requests3GEMMs+3pointwise calls versus3GEMMs+1pointwise call; actual internal kernel counts remain unknown. [E2]
- The same Lt selections report status0 split-K attributes4/4/8 and10/5/10 at p/h/m, reduction enum2, checked workspace0.5–5MiB within32MiB allocated outside clocks. These are queried attributes of the selected configurations. They establish neither executed parallel reduction nor its speedup, SASS, kernel count, or instruction units. [E3]
- Actual old/shared-tile Mapal Contract images prove the old functions lack shared LDS/STS/BAR mnemonics and the cooperative16×32/K8 functions contain them. Static counts include loop bodies and padding. Runtime register counts40 versus79 and local_bytes0 are observed resources, not achieved occupancy or traffic. No library, deeper8×64/K16, Exact or TF32 image is admitted yet. JIT13.3.44 versus nvdisasm12.8 limits complete decoding. [E4]
- The composed clocks include completion. Mapal arena creation, input generation and final free are outside the measured steady region; a nonzero arena slot is reused inside it. Events end after synchronization, so they include submission and completion-wakeup/end-enqueue gaps. The audit found no proved missing-sync, unit or output-copy-in-clock defect. Input/cache preparation and allocation strategies still differ across arms. [E3]
- Existing lifetime/fusion facts eliminate unused raw allocations on tested graphs;640 ordinary plus28 separate traced counter processes pass. No ordinary latency benefit was measured. The frozen composed compiler predates this correction, but its initial arena allocation/free are outside its existing steady clock. [E5]

## Separate reduction-permission experiment

**P2 — Explicit error-bounded reassociation, only as a separate track.** The Lt split-K attributes motivate a controlled question, not a change to Mapal Contract. First use supported Lt configurations to test split-K1 against the selected value while holding every other available configuration attribute fixed, querying/checking legality/workspace, and freezing opaque bytes. If no matched legal pair exists, record that limitation; do not compare unrelated heuristic indices as a one-factor experiment. Capture actual dispatch/images separately before describing reduction organization.

A planned Mapal parallel-partial/tree alternative would need a separately named numerical permission, explicit partial/final reduction semantics and storage/completion plan, and an a-priori outward error rule validated before tuning. This is not `TileKSplit` address decomposition. Keep ordered-FMA output as a distinct baseline and report ordered-bit failures rather than absorb them into the relaxed result. Use full bounded/adversarial outputs plus the preregistered representative/checkpoint contract, include partial workspace/allocation/extra launches in the appropriate clock, and freeze selection before confirmation. If speedup disappears under matched controls, or the promised error contract fails, reject that alternative. Its success would establish only a result under the new permission, never a silent improvement to the current ordered language.

Tensor-core use and a missing reduced-precision IR fact are unproved. No precision-policy experiment is required to explain the present FP32 gap. Actual library SASS may identify instruction families; static presence still establishes neither dynamic traffic/occupancy nor the latency cause.

## Promotion boundary

A source-known legal realization plus a numerical pass is preparation, not profitability. Every candidate must survive explicit failures, same-host unchanged controls, independent tuning/confirmation, appropriate whole-program timing and a defined shape/face scope. New instrumentation remains separate. Repeat promising gains with changed arm order and another independent host before a broad selection rule. Existing16K results remain a separate baseline: cuBLAS was faster on every tested16K face, and a small CUTLASS FMA lead was not repeatably established. [E8]

Proposed order: finish the pending image pilot; prepare matched clocks/flow inventories and a bounded ordered geometry factorial; measure the already integrated allocation correction with the inclusive boundary; use the resulting evidence to choose dispatch, retention, fusion/layout or explicitly relaxed reduction work. No shared code change is proposed here.

Current implementation work is narrower than these performance experiments: [HARDWARE-SELECTION-AUDIT.md](../fact-driven-selection/hardware-selection-audit.md) confirms existing hardware derivation and intentional warp-fill budgeting. It recommends the proven actual-arithmetic selection/emission connection correction while retaining geometry/policy. Prior blanket small-M fitting is already measured; it is not a newly proposed fix or a reason to rerun completed preparation sweeps.
