# Residual MLP fused library reference review

This is an isolated benchmark implementation. It adds source-supported cuBLASLt and CUTLASS bias/ReLU epilogues for the same residual MLP and immutable inputs, alongside preserved naive/cuBLAS controls. There has been no CUDA compilation, GPU execution, rental or production change for this packet. Primitive CUTLASS measurements are a separate completed study and are not substituted for these composed measurements.

`CONTRACT.md` defines the exact DAG, tensor bytes, accepted numerical scope, descriptor reinterpretation, finite candidates, tuning/confirmation order and clock boundaries. `run_native.py` is the bounded entrypoint; `composed_native.cu` loads the frozen inputs and emits raw values and timing protocol; `native_plans.hpp` implements the separate library plans; `validate_native.py` independently admits exact identities and numerical observations before acknowledging any timed request.

The frozen `reference.cu`, fixture header and numerical rule are copied byte-for-byte from the admitted parent packet, whose manifest is recorded in `frozen-source-receipt.json`. Named native GEMMs and pointwise functions are reused through an include with the old main renamed. No frozen compute call, Mapal LLVM/PTX, input formula or historical acceptance threshold is edited. New plans call the preserved pointwise kernels. All three case input binaries and matrix reference/bound files are byte-bound by `reference-data/manifest.json`; tiny thresholds are the same parent rule evaluated before any new GPU result.

CUTLASS is pinned to commit91843b71d90737e0a9b86f7d9df213cff5a3526f, copied unchanged from the reviewed primitive packet. `pinned-cutlass-receipt.json` binds all908 included files to that packet. Seven finite whole-program SIMT geometries are explicit in the contract/runner/native compile selector. Each geometry is built separately; a base-only build has no CUTLASS instantiation, so unsupported candidate geometry cannot erase Lt/controls. No universal selector or claim of global optimality follows from this finite space.

The numerical gate compares each actual FP32 word with both original scalar faces using exact Fractions against the unchanged binary64 acceptance threshold. Libraries have a bounded acceptance; naive additionally requires ordered-fmaf words. Full tiny checks cover every input word, all six intermediate/final tensors and an independent final-only request. Representative checks cover the original 256 cells per stage and final; every timed request's selected y cells are observed after clocks. Hidden fused accumulators are not directly observed: checker-only plain matmuls supply hraw/mraw, while final-only timing omits those extra requests. This is an inherited acceptance contract, not a new proof that every frozen propagated threshold is an outward bound for all possible library reductions.

The controller hashes the requested input, executable and both manifests before launch, again before ACK, and after completion. It binds backend/fusion, shape, compiled candidate and exact tile/warp/epilogue/stride receipts, mode/tuning, Lt selected-index tuple and a fresh nonce. Lt held-out identity additionally requires the actual selected opaque algorithm bytes to match the selecting tuning receipt. Equal heuristic positions alone are insufficient. No whole-program timing can begin before the independent prefix check sends its nonce ACK.

Ordinary processes remove inherited known instrumentation variables, require TF32 override0, and record the actual queried library math/version and GPU/runtime values. Compilation, constructors, descriptors, workspace, heuristic queries, independent checks and observations are outside steady clocks. Any CUTLASS operator-internal host setup still performed by its actual run API remains inside clocks. All variants keep the same named tensor buffers; Lt's explicit32MiB workspace and unmeasured private allocations remain separately labeled.

Process limits are1200s global,120s/build and30s/work call, with suggested outer1230s. These are ceilings, not measured compile-cost predictions. Each build/work starts a fresh process group. Timeouts, numerical rejection and cancellation kill that exact owned group, including descendants after an exited leader. SIGTERM/SIGINT cleanup prevents subsequent launches. Unsupported configurations and partial raw evidence survive in summary/receipts; required missing arms yield exit2.

Focused CPU verification is explicit about scope:

- `cpu-validation-sealed/results.json`: full three-case fixtures pass; malformed values, indices, input bits, missing/duplicate completion or samples, wrong candidate/config/mode/tuning/nonce and absent plan receipts reject.
- `cpu-handshake-sealed/results.json`: real subprocess pipes acknowledge an honest synthetic-value fixture; incorrect values/nonces fail before ACK; same-index changed Lt algorithm identity and missing Lt receipts reject; a silent child is bounded.
- `cpu-cleanup-sealed/results.json`: real compiler descendants and an exited work leader's stdout-holding descendant cannot execute their post-timeout marker.
- `cpu-cancel-sealed/results.json`: real SIGTERM during build and SIGINT during work terminate owned descendants and reject further launches.
- The independent gap reviewer CPU-compiles verbatim native C++ argv/input guards, request printf and ACK source with the actual frozen fixture structs/binaries. Its54 positive and12 negative vectors pass; this complements synthetic value/clock fixtures with actual-source protocol compatibility.

All synthetic clocks are protocol fixtures and are never performance evidence. Independent source review verifies the Lt layout/bias axis, pedantic precision/workspace rules, separate CUTLASS C/D strides, FP32 epilogue order, checker/final-only graph distinction and parent clock boundary. Final support/resources/numerical admission/tuning/timings remain GPU obligations. The exact sealed packet digest and check-only/archive inventory receipts are supplied after this review completes.

To measure compiler-fusion advantage, rerun the admitted Mapal/Torch controls on the same GPU and admit those results separately. The native-only summary deliberately records that they are absent. Historical results from other runs are context, never paired evidence. A graph-enabled Torch arm remains a subsequent explicit configuration.

Reproduce CPU checks into fresh external directories with `python3 test_validation.py --out ABS_FRESH`, and equivalently `test_handshake.py`, `test_cleanup.py` and `test_cancel.py`. The archived receipts preserve the actual completed local runs; tests do not touch CUDA. Run `python3 run_native.py --check-only` to verify every sealed payload byte without compilation or GPU use.
